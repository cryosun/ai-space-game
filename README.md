# COSMIC ARENA

Многопользовательский космический шутер с видом сверху (top-down space shooter) для локальной сети.
Сервер и клиент запускаются на одной машине, остальные игроки подключаются через браузер по IP — ничего ставить не нужно.

- **Стек:** Node.js + Express + Socket.io, HTML5 Canvas + чистый JS, Web Audio API (звук генерируется программно, внешних файлов нет).
- **Архитектура:** авторитетный сервер. Вся физика, столкновения, ИИ и спавн — на сервере (60 Гц), клиент отправляет только ввод и отрисовывает состояние с интерполяцией.
- **Статистика** сохраняется в `stats.json` и не теряется между перезапусками.

## 1. Требования

| Что | Версия |
|---|---|
| Node.js | 18+ (проверено на 22.22.3) |
| npm | идёт вместе с Node |
| Браузер | любой современный: Chrome, Edge, Firefox, Safari (нужны Canvas2D + Web Audio) |

Внешних ассетов, картинок и звуков не требуется — всё внутри кода.
Игра одинаково работает на **Windows 11**, Linux и macOS — отдельные установщики/сборки не нужны.

### Установка Node.js

**Windows 11:** откройте [nodejs.org](https://nodejs.org/), скачайте кнопкой **LTS** (файл `node-vXX.msi`), установите со стандартными настройками и откройте **новый** терминал (PowerShell или Windows Terminal). Перезапуск терминала обязателен — иначе `node` не попадёт в `PATH`.

**Linux / macOS:** через nvm или менеджер пакетов (`sudo apt install nodejs npm` и т.п.).

Проверить, что всё встало:

```powershell
node -v      # Windows (PowerShell/CMD)
npm -v
```

```bash
node -v      # Linux / macOS
npm -v
```

> Если Node установлен через **nvm** (Linux/macOS) и команда отвечает `node: команда не найдена`, выполните перед запуском:
>
> ```bash
> export PATH="$HOME/.nvm/versions/node/v22.22.3/bin:$PATH"
> # или просто: nvm use 22
> ```

## 2. Запуск сервера (2 команды)

**Windows 11 (PowerShell или Windows Terminal):**

```powershell
cd путь\к\ai_game      # например: cd C:\Users\Имя\ai_game
npm install            # нужен только один раз
npm start              # или: node server.js
```

**Linux / macOS:**

```bash
cd ai_game
npm install     # нужен только один раз
npm start       # или: node server.js
```

> В Windows папку с проектом нельзя запускать «в один клик» двойным щелчком — сервер должен работать в открытом терминале. Закроете окно терминала — сервер остановится.
>
> При **первом** запуске Windows спросит «Разрешить Node.js обмен данными в частных сетях?» — поставьте галочку **Частные сети** и нажмите **Разрешить доступ**. Без этого друзья не подключатся.

В консоли появится примерно такое (в Windows вместо `enp131s0` будет имя адаптера `Ethernet`/`Wi-Fi`):

```
  ╔══════════════════════════════════════════════╗
  ║            C O S M I C   A R E N A           ║
  ╚══════════════════════════════════════════════╝

  Вы:           http://localhost:3000
  Для друзей:   http://192.168.8.197:3000   <-- скиньте эту ссылку (Ethernet)

  Прочие адреса (VPN/Docker — обычно не нужны):
    vEthernet (WSL)  http://172.24.0.1:3000
  ...
```

Сервер сам определяет физический сетевой интерфейс (в Linux — по маршруту по умолчанию, в Windows — по имени адаптера) и показывает адреса VPN/Docker/WSL отдельно — чтобы вы не отправили друзьям адрес вроде `tun0` или `vEthernet (WSL)`, он у них не откроется.

**Сменить порт:**

```powershell
$env:PORT=8080; npm start      # Windows PowerShell
```
```cmd
set PORT=8080 && npm start     :: Windows CMD
```
```bash
PORT=8080 npm start            # Linux / macOS
```

**Остановить:** `Ctrl+C` в том же окне терминала (статистика при этом сохраняется).

## 3. Как позвать друзей

### Вариант А — одна локальная сеть (основной сценарий)

1. Запустите сервер, как выше.
2. Скопируйте строку **«Для друзей»** — например `http://192.168.8.197:3000`.
3. Отправьте её друзьям. Они открывают ссылку в браузере, вводят ник, выбирают корабль и цвет → **ВОЙТИ НА АРЕНУ**.

Все игроки должны быть в той же сети (тот же Wi-Fi/роутер/switch).

### Если друзья не подключаются — чек-лист

1. **Файрвол.** Порт 3000 чаще всего блокирует именно он.
   - **Windows 11:** при первом запуске разрешите Node.js доступ в **частных сетях**. Если окно пропустили — добавьте правило вручную (PowerShell **от имени администратора**):
     ```powershell
     netsh advfirewall firewall add rule name="Cosmic Arena" dir=in action=allow protocol=TCP localport=3000
     ```
     Проверить состояние профиля сети: **Параметры → Сеть и Интернет → Ethernet/Wi-Fi** — сеть должна быть **«Частная»**, а не «Общедоступная» (на «общедоступной» Windows блокирует входящие подключения).
   - **Ubuntu/Debian:** `sudo ufw status`, затем `sudo ufw allow 3000/tcp`.
   - **Fedora/RHEL:** `sudo firewall-cmd --add-port=3000/tcp && sudo firewall-cmd --reload`.
2. **Тот же subnet.** Сравните IP: у вас `192.168.8.197`, у друга должен быть `192.168.8.x`. Если у него `192.168.0.x` или мобильный интернет — он в другой сети.
3. **Изоляция клиентов на Wi-Fi.** На гостевых сетях и в общежитиях роутер часто запрещает клиентам видеть друг друга — подключитесь по кабелю или через свой роутер.
4. **Проверка с другой машины:** откройте `http://<ваш-IP>:3000` в браузере на другом устройстве. Если страница открылась — проблема у клиента; если «не удаётся» — блокирует файрвол или сеть. Из терминала то же самое: `curl -I http://192.168.8.197:3000` (Windows PowerShell: `curl.exe -I http://192.168.8.197:3000`) должен вернуть `HTTP/1.1 200 OK`.
5. **VPN.** Если у вас или друга включён VPN (Amnezia, WireGuard и т.п.), трафик может уходить в туннель. Выключите VPN на время игры.

### Вариант Б — друзья не в вашей сети (через интернет)

Есть два пути: **Б1** — открыть порт на роутере (нужен публичный/белый IP), **Б2** — туннель (роутер трогать не нужно, работает всегда).

#### Б1. Проброс порта на роутере (GL.iNet Flint 2 / GL-MT6000)

Подготовка на Windows:

1. Узнайте локальный IP ПК — он напечатан в консоли сервера в строке **«Для друзей»** (например `192.168.8.197`). Или в PowerShell: `ipconfig` → «IPv4-адрес».
2. Закрепите этот адрес, чтобы он не менялся после перезагрузки: в админке роутера **Clients → резервирование IP (Static IP)** по MAC-адресу, либо задайте статический IP в Windows.
3. Разрешите порт в файрволе Windows (PowerShell **от администратора**):
   ```powershell
   netsh advfirewall firewall add rule name="Cosmic Arena" dir=in action=allow protocol=TCP localport=3000
   ```

Настройка роутера GL.iNet (прошивка 4.x):

4. Откройте админку: `http://192.168.8.1` (пароль задан при первом включении).
5. Перейдите в **NETWORK → Firewall** и на вкладку **Port Forwards** (в старых прошивках — *Firewall → Port Forwarding*; в OpenWrt-режиме — *Network → Firewall → Port Forwards*).
6. Добавьте правило:

   | Поле | Значение |
   |---|---|
   | Name | `cosmic-arena` |
   | Protocol | `TCP` |
   | External zone | `wan` |
   | External port | `3000` |
   | Internal zone | `lan` |
   | Internal IP | `192.168.8.197` (IP вашего ПК) |
   | Internal port | `3000` |

7. Нажмите **Apply / Save**.
8. Узнайте ваш публичный IP: `https://2ip.ru` или `curl ifconfig.me`. Отдайте друзьям ссылку `http://<публичный-IP>:3000`.

**Проверка «извне»:** отключите Wi-Fi на телефоне (оставьте мобильный интернет) и откройте `http://<публичный-IP>:3000`. Открылось — значит друзья тоже зайдут.

**Ссылка не должна меняться (DDNS).** Домашние провайдеры часто меняют публичный IP. GL.iNet умеет бесплатный динамический DNS: **APPLICATIONS → DDNS**, включите — получите домен вида `вашеимя.glddns.com`, и ссылка для друзей станет постоянной: `http://вашеимя.glddns.com:3000`.

**Главная причина, почему проброс «не работает» — CGNAT (серый IP).** Проверка: сравните **WAN IP** из админки роутера (*INTERNET / Internet status*) с публичным IP с `2ip.ru`. Если они **различаются** — провайдер спрятал вас за своим NAT, и проброс порта в принципе не сработает. Решения: попросить у провайдера **публичный («белый») IP** (обычно 50–150 ₽/мес или бесплатно по заявке) либо использовать туннель из Б2.

#### Б2. Туннель — роутер и проброс не нужны

Работает даже за CGNAT. Сервер остаётся у вас на Windows, а публичную ссылку выдаёт сервис-туннель:

```powershell
# Windows 11: установка и запуск (пока сервер Cosmic Arena работает на :3000)
winget install --id Cloudflare.cloudflared
cloudflared tunnel --url http://localhost:3000
```

Либо `ngrok http 3000` (нужен бесплатный аккаунт и токен). В выводе появится публичный `https://...`-адрес — его и отправляете друзьям. Туннель живёт, пока открыт терминал; закрыли — доступ пропал.

> Linux: `sudo apt install cloudflared` (или `.deb` с [github.com/cloudflare/cloudflared](https://github.com/cloudflare/cloudflared/releases)).

Обратите внимание: игра не имеет паролей и шифрования — любой, кто узнал ссылку, попадёт на арену. Не публикуйте ссылку открыто и закрывайте туннель после игры.

### Вариант В — поиграть одному

Откройте `http://localhost:3000` — можно играть в одиночку (боты в режиме «Выживание» создают всю компанию).

## 4. Сколько может быть игроков

**Жёсткого лимита в коде нет** — ограничение только аппаратное и сетевое.

| Сценарий | Рекомендация |
|---|---|
| Комфортно на LAN | 2–8 игроков |
| Предел по ощущениям | ~16 игроков (начнёт страдать трафик, особенно в полной волне ботов) |
| Боты в «Выживании» | до 38 одновременно (растёт с номером волны) |

**Трафик (реальные замеры):** пакет состояния — в среднем **850 байт** при 1 игроке и 3 ботах, рассылается 30 раз в секунду, то есть ≈ **25 КБ/с (~200 Кбит/с) на каждого клиента**.

Оценка на полной волне (8 игроков + 34 бота + ~50 снарядов) — около **10 КБ на пакет**, то есть до **2.6 Мбит/с на клиента**. Для LAN это норма, но:

- если друзья подключаются через интернет, ваш **исходящий** канал должен вместить `2.6 Мбит/с × число игроков` (4 игрока ≈ 10 Мбит/с);
- чем больше игроков, тем больше нагрузка на CPU сервера (симуляция 60 Гц).

Если нужно больше людей — увеличьте `NET_HZ` → нет, наоборот: уменьшите `NET_HZ` до 20 и `MAX_POWERUPS`, а также ограничьте максимум ботов в формуле волны (см. «Настройка»).

## 5. Управление

| Клавиша | Действие |
|---|---|
| `W` `A` `S` `D` или `←` `↑` `↓` `→` | движение с космической инерцией (есть дрейф) |
| Мышь | прицел — нос корабля плавно доворачивается за курсором |
| `ЛКМ` (удерживать) | огонь |
| `Space` или `ПКМ` | рывок (Dash): 0.35 с неуязвимости + рывок 950 px/с, перезарядка 3 с |
| `Tab` | расширить/свернуть таблицу лидеров |
| `M` | звук вкл/выкл |
| `Esc` | закрыть окно статистики |

**На телефоне/планшете** управление автоматическое: левая половина экрана — виртуальный стик движения, касание правой половины — прицел и огонь.

## 6. Режимы игры

Арена одна общая — все, кто подключился, попадают в один матч.

### 6.1 Каждый сам за себя (FFA / Deathmatch)
- Все против всех. Своих не бывает, дружественный огонь включён.
- Погиб — возрождение через **3 секунды** в случайной безопасной точке (сервер выбирает место подальше от противников).

### 6.2 Выживание (Co-op Survival)
- Все игроки — одна команда, **дружественного огня нет** (своих не задеть).
- На карту волнами наступают боты. С каждой волной их больше и они крепче/быстрее.
- Между волнами **5 секунд передышки**: щиты восстанавливаются до максимума, корпус получает +20 HP.
- Гибель игрока — обычное возрождение через 3 с, матч не заканчивается.

### Кто переключает режим
- **Хост** — первый подключившийся игрок. Он видит кнопки `FFA` / `ВЫЖИВАНИЕ` активными и меняет режим мгновенно.
- **Остальные — голосованием:** нажатие на кнопку отправляет голос. Режим меняется, когда за него проголосовало **больше половины** всех игроков. Прогресс голосования виден в килл-фиде.
- Если хост вышел — хостом автоматически становится следующий игрок.

## 7. Корабли

| Корабль | Корпус | Щит | Скорость | Урон | Темп огня | Особенность |
|---|---|---|---|---|---|---|
| **Interceptor** | 80 | 60 | 300 px/с | 9 | 0.13 с | самый быстрый и вёрткий, но хрупкий |
| **Vanguard** | 110 | 85 | 260 px/с | 12 | 0.16 с | золотая середина |
| **Spectre** | 155 | 110 | 218 px/с | 16 | 0.20 с | тяжёлый бронированный «танк» |

Общее для всех:
- **Щит** восстанавливается сам по **26 единиц/с**, но только если корабль не получал урон **4 секунды**.
- **Корпус (HP) сам не восстанавливается** — только ремкомплектом или +20 HP между волнами.
- Скорость снаряда 790–950 px/с, время жизни снаряда 2.2 с.
- После возрождения действует 2 с неуязвимости (мигающий белый круг).

## 8. Бонусы

Спавнятся каждые ~8 секунд (интервал случайно 5.6–10.4 с) в случайных точках, одновременно на карте не больше **6**.

| Бонус | Иконка | Эффект |
|---|---|---|
| Ремкомплект | ✚ зелёный | +45 HP (не выше максимума) |
| Тройной выстрел | ⋔ жёлтый | 10 секунд стрельбы веером из 3 снарядов |
| Ускорение перезарядки | ⚡ голубой | 10 секунд: темп огня ускорен в ~2.2 раза |

Все бонусы видны на мини-карте маленькими точками.

## 9. Боты и волны (режим «Выживание»)

| Тип | HP | Скорость | Оружие | Поведение |
|---|---|---|---|---|
| **Разведчик** (красный) | 40 | 200 px/с | одиночный выстрел, урон 6 | держит дистанцию ~340 px, облетает по дуге |
| **Крейсер** (оранжевый) | 170 | 95 px/с | веер из 3 снарядов, урон 9 | медленный «танк», стреляет залпами |
| **Камикадзе** (фиолетовый) | 55 | 245 px/с | таран | летит прямо на ближайшего игрока и взрывается при контакте (урон 46 в радиусе 120 px) |

**Формула волны N:**

- количество ботов = `min(38, 2 + floor(N × 1.45))` — 3, 4, 6, 7, 9, 10, 12… до 38;
- прочность бота × `(1 + (N−1) × 0.14)`;
- скорость бота × `(1 + (N−1) × 0.03)`;
- состав: волна 1 — только разведчики; со 2-й появляются крейсеры; с 4-й — камикадзе;
- спавн — по краям карты партиями каждые 0.45 с, чтобы волна «накатывалась», а не появлялась мгновенно.

## 10. Интерфейс

- **Мини-карта** (правый нижний угол) — игроки, боты, бонусы и рамка текущего вида камеры.
- **Таблица лидеров** (правый верхний угол, `Tab` — расширенная) — место, ник, очки, смерти, точность, титул. Очки: `убийства игроков × 3 + убитые боты`.
- **Килл-фид** (левый нижний угол) — «Палач уничтожил Жертву», «Тестер подобрал Ремкомплект», голосования, входы/выходы.
- **Крупные уведомления** (центр) — серии убийств и старт волн.
- **Полосы состояния** (низ по центру) — HP, щит, перезарядка Dash, таймеры бонусов.
- **Оверлей смерти** — «УНИЧТОЖЕН» и отсчёт до возрождения.
- **Кнопки** — переключатель режима (или голосование) и иконка звука в правом верхнем углу.
- Здоровье и щит противников рисуются полосками прямо над кораблями.

## 11. Звук

Полностью процедурный (`public/sound.js`), внешних `.mp3`/`.wav` нет — всё синтезируется осцилляторами, белым шумом и фильтрами:

- лазер — короткий спадающий импульс (для своих и врагов разный тембр);
- попадание по щиту — звонкий «тик»; по корпусу — глухой удар;
- взрыв — белый шум через low-pass + низкий «бум», громкость зависит от масштаба;
- рывок — whoosh с восходящей частотой; подбор бонуса — арпеджио;
- старт волны, возрождение, смерть, ачивки.

Браузеры запрещают звук до первого действия пользователя — звук включается автоматически при нажатии «ВОЙТИ НА АРЕНУ». Кнопка `🔊`/`🔇` или клавиша `M` отключает звук.

## 12. Статистика и титулы

Сервер пишет по каждому нику в `stats.json`:

- убийства игроков и убийства ботов (отдельно);
- смерти и соотношение K/D;
- максимальная пройденная волна;
- нанесённый урон и точность (`попадания / выстрелы`, %).

Записи **накапливаются между запусками сервера** (файл перезаписывается каждые 5 с и при остановке). Посмотреть таблицу можно на экране входа по кнопке **«📊 Статистика игроков»**, а сырые данные — по адресу `http://localhost:3000/api/stats`.

### Титулы (присваиваются в реальном времени, первый подходящий сверху вниз)

| Титул | Условие |
|---|---|
| **Берсерк** | серия убийств без смерти ≥ 8 |
| **Снайпер** | точность ≥ 45% при ≥ 25 попаданиях |
| **Охотник на ботов** | ≥ 25 убитых ботов |
| **Ас** | ≥ 10 убийств игроков |
| **Неуязвимый** | ни одной смерти и ≥ 3 убийства |
| **Пушечное мясо** | ≥ 8 смертей и убийств не больше 40% от них |
| **Живучий** | ≥ 5 смертей |

### Уведомления о серии

- **Double Kill** — 2 убийства за 3 с, **Triple Kill** — 3, **Quadra Kill** — 4;
- **Rampage** — 5 убийств подряд или серия из 3 без смерти;
- **Unstoppable** — 6 и больше;
- **Godlike** — серия из 10 без смерти.

## 13. Технические детали

### Архитектура

```
Браузер (клиент)                       Node.js (сервер)
─────────────────                      ─────────────────
input (60 Гц): клавиши, угол мыши  ──►  симуляция 60 Гц: физика, хитбоксы,
                                        ИИ ботов, волны, спавн, урон, счёт
отрисовка с интерполяцией          ◄──  state 30 Гц: позиции, HP, снаряды,
(задержка 80 мс)                        бонусы, таблица лидеров, события
```

Сервер — единственный источник истины: клиент ничего не решает сам, поэтому рассинхрон и читы через правку клиента невозможны. Клиент присылает только 7 чисел/флагов ввода.

### Сеть

- Транспорт: Socket.io (WebSocket с автоматическим fallback на polling), **один TCP-порт 3000**.
- Отправка ввода: `input` (направления, `fire`, `aim` — абсолютный угол в радианах) и отдельное событие `dash` (мгновенное, а не удержание).
- Пакет `state`: `{ t, mode, map, hostId, wave, waveState, players[], bots[], bullets[], powerups[], lb[], fx[], events[], votes }`; координаты округлены до 0.1 px.
- `fx` и `events` — разовые события (взрывы, попадания, рывки, подборы, килл-фид, анонсы); они приходят только в одном пакете и на клиенте превращаются в частицы и звуки.
- Интерполяция: клиент хранит буфер из последних 24 снапшотов и рисует мир в момент `последний_t − 80 мс`, линейно смешивая два соседних снапшота (углы — по кратчайшей дуге). Благодаря этому 30 Гц выглядят как 60+ FPS.
- Сервер не «догоняет» клиента: если пакеты потерялись, клиент просто интерполирует между тем, что есть.

### Частицы и графика (клиент)

Параллакс-звёзды в 3 слоя с бесшовной тайловой прокруткой, шлейфы двигателей, взрывы с ударными волнами, искры попаданий, тряска камеры, glow через `shadowBlur`, неоновые полигональные корабли (векторная отрисовка, без спрайтов).

### Производительность

- Симуляция: O(снаряды × цели), при 50 снарядах и 40 кораблях — ~2000 проверок столкновений за тик, то есть ~120 тыс./с. Легко держит один поток Node.
- Клиент рисует только то, что попадает в кадр (частицы и звёзды отсекаются по границам экрана).
- DPR ограничен 2, чтобы 4K-мониторы не убивали FPS.

## 15. Настройка (правка констант)

Почти всё настраивается в начале [server.js](server.js):

| Константа | Значение | Смысл |
|---|---|---|
| `PORT` | 3000 | порт; можно задать переменной окружения `PORT` |
| `STATS_FILE` | `./stats.json` | путь к файлу статистики; переменная `STATS_FILE` (например `/data/stats.json` на хостинге) |
| `MAP_W` / `MAP_H` | 3200 / 2400 | размер арены |
| `TICK_HZ` | 60 | частота симуляции |
| `NET_HZ` | 30 | частота рассылки состояния (снизить → меньше трафика) |
| `SHIELD_REGEN_DELAY` / `SHIELD_REGEN_RATE` | 4 с / 26 | восстановление щита |
| `RESPAWN_TIME` | 3 с | возрождение |
| `DASH_COOLDOWN` / `DASH_TIME` / `DASH_SPEED` | 3 с / 0.35 с / 950 | рывок |
| `INTERMISSION_TIME` | 5 с | передышка между волнами |
| `POWERUP_INTERVAL` / `MAX_POWERUPS` | 8 с / 6 | бонусы |
| `SHIPS` | — | характеристики кораблей |
| `BOT_TYPES` | — | характеристики ботов |
| `POWERUPS` | — | эффекты бонусов |

Формула размера волны — в функции `startWave()`, цвета кораблей — в `COLORS` в [game.js](public/game.js).

## 16. Если что-то не работает

| Симптом | Причина и решение |
|---|---|
| Windows: `"node" не является внутренней или внешней командой` | терминал открыт до установки Node — закройте и откройте заново, либо перезагрузитесь |
| Linux/macOS: `node: команда не найдена` | Node установлен через nvm — см. раздел «Требования» |
| `Error: listen EADDRINUSE :::3000` | порт занят: запустите на другом порту (`$env:PORT=3001; npm start` в PowerShell) или закройте прошлый процесс |
| Друзья не могут открыть ссылку | файрвол (Windows: `netsh advfirewall firewall add rule ...`; Linux: `sudo ufw allow 3000/tcp`), другая подсеть, изоляция Wi-Fi, включённый VPN |
| Открывается на «общедоступной» сети, но не с других устройств | переключите сеть Windows в **«Частная»** (Параметры → Сеть и Интернет) |
| Зашёл, но «Сервер недоступен» | сервер не запущен или выключился — смотрите консоль |
| Нет звука | звук включается после первого клика; проверьте кнопку `🔊` и вкладку браузера |
| Лаги, рывки картинки | мало игроков на слабом Wi-Fi, много ботов, вкладка в фоне; снизьте `NET_HZ` |
| Чёрный экран | обновите страницу (F5); нужен браузер с Canvas2D |
| Хочу сбросить статистику | остановите сервер и замените содержимое `stats.json` на `{}` |

## 17. Размещение на хостинге (24/7, без своего ПК)

Нужно, если не хочется держать включённым свой компьютер, а ссылка должна быть постоянной и доступной откуда угодно.

Важное про этот проект при деплое:

- Это **один Node-процесс** с WebSocket (Socket.io). Подходит любой хостинг с Node и поддержкой WebSocket. Статические хостинги (GitHub Pages, обычный «хостинг сайтов», PHP-хостинг) **не подойдут** — там нет Node.
- Сервер читает `PORT` из переменной окружения — большинство платформ (Render, Railway, Fly.io, Heroku) задают её сами, код менять не нужно.
- Клиент подключается к тому же домену (`io()`), поэтому HTTPS/прокси в коде настраивать не надо.
- **Статистика** пишется в `stats.json`. На бесплатных тарифах диск «эфемерный» — файл стирается при перезапуске. Решение: `STATS_FILE=/data/stats.json` + постоянный том/диск.
- Игра **без пароля**: на публичном хостинге любой, кто знает адрес, попадёт на арену.

### Вариант 1 — Docker (универсальный)

В проекте уже есть `Dockerfile` и `docker-compose.yml`.

На локальной машине или VPS с Docker:

```bash
docker compose up -d          # игра на http://<IP-машины>:3000
```

Без compose:

```bash
docker build -t cosmic-arena .
docker run -d --name cosmic-arena -p 3000:3000 \
  -e STATS_FILE=/data/stats.json -v arena_data:/data cosmic-arena
```

Любая облачная платформа, умеющая `Dockerfile` (Render, Railway, Fly.io, Google Cloud Run), соберёт образ сама.

### Вариант 2 — VPS (Ubuntu): systemd + nginx

Самый гибкий вариант: свой сервер, свой домен, HTTPS.

1. Подключиться: `ssh user@<IP-VPS>`.
2. Установить Node.js, скопировать проект на сервер (`git clone` или `scp`), затем `npm ci --omit=dev`.
3. Создать `/etc/systemd/system/cosmic-arena.service`:

```ini
[Unit]
Description=Cosmic Arena
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/ai_game
ExecStart=/usr/bin/node server.js
Environment=PORT=3000
Environment=STATS_FILE=/var/lib/cosmic-arena/stats.json
Restart=always
User=www-data

[Install]
WantedBy=multi-user.target
```

4. Включить сервис: `sudo systemctl daemon-reload && sudo systemctl enable --now cosmic-arena`.
5. Открыть порт (если играете без nginx): `sudo ufw allow 3000/tcp`.
6. (Для домена и HTTPS) поставить nginx как reverse proxy и добавить конфиг:

```nginx
server {
    listen 80;
    server_name arena.example.com;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;          # WebSocket
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_read_timeout 300s;
    }
}
```

7. Выпустить бесплатный сертификат: `sudo certbot --nginx -d arena.example.com`. Друзьям отдаёте `https://arena.example.com`.

> Обязательно увеличьте `proxy_read_timeout` (по умолчанию 60 с) — иначе долгие игровые сессии с редким трафиком могут обрываться прокси.

### Вариант 3 — PaaS без администрирования (Render / Railway / Fly.io)

1. Выложите проект в репозиторий на GitHub (`.gitignore` уже подготовлен — `node_modules` и `stats.json` не попадут в коммит).
2. На платформе создайте новый **Web Service** и подключите репозиторий.
3. Build — `npm install`, Start — `npm start` (Render и Railway определяют это автоматически). На Docker-платформах выберите сборку из **Dockerfile**.
4. Переменные окружения: `STATS_FILE=/data/stats.json` — если у тарифа есть постоянный диск, иначе статистика будет сбрасываться.
5. Платформа сама выдаёт публичный `https://...` адрес и сама задаёт `PORT` — этот адрес отдаёте друзьям.

### Ограничения бесплатных тарифов

- **Засыпание.** Render Free усыпляет сервис после ~15 минут без трафика: первый заход друзей будет долгим (10–60 с), дальше — нормально.
- **Эфемерный диск.** `stats.json` теряется при каждом деплое/перезапуске, если не подключён постоянный том.
- **WebSocket.** Убедитесь, что тариф его поддерживает (Render / Railway / Fly.io — да).
- **Трафик.** На полной волне — до ~2.6 Мбит/с на клиента (раздел 4); сверяйтесь с лимитами тарифа.
